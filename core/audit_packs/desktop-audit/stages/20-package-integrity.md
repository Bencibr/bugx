# Stage 20: Package Integrity & Update Channel (白盒：打包完整性与更新通道)
<!-- L1:START -->
1. 核对安装包/归档的签名与校验（代码签名、公证、哈希清单）。
2. 检查打包内是否含未压缩的源码/映射/凭据（asar 解包、sourcemap、`.env`）。
3. 检查自更新通道：更新源是否强制 HTTPS、是否校验签名、是否可降级/劫持。
4. 产出 `package-integrity-findings`。
<!-- L1:END -->
<!-- L2:START -->
## 操作指南
- 解包产物属**只读**操作，禁止改动用户已安装的程序目录。
- 泄露判定必须给出具体文件与内容类型（如 sourcemap 含原始路径、打包内 .env）；
  发现真实凭据时**只记录位置与类型，绝不复制内容**。
- 更新通道必须回答：能否被中间人替换？能否回滚到含漏洞版本？签名缺失是否 fail-closed？
- 复用既有 `web_conformance` 探针覆盖前端资源一致性（不新造探针）。
<!-- L2:END -->

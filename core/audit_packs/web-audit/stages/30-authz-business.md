# Stage 30: Authorization & Business Logic (越权与业务逻辑推演)
<!-- L1:START -->
1. 构造越权假设：基于 Attack Graph 推演水平越权 (IDOR) 与垂直越权路径。
2. 执行交叉请求：使用 User A 身份操作 User B 专属资源 (如 orders, profile)。
3. 双向对照验证：必须提供 `status=200` 越权利用与 `status=403` 负向合法拦截报文。
4. 遇到签名/拦截阻断，触发反思回溯机制定位鉴权/签名源码并自愈。
<!-- L1:END -->
<!-- L2:START -->
## 操作指南
- 重点关注包含资源 ID、租户 ID 的 REST 端点。
- 严格验证业务完整性：只读泄露属于水平越权，越权修改/删除属于高危越权。
- 必须产出严格的对照证据，防止因鉴权缺失导致的假阳性。

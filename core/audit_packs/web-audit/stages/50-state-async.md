# Stage 50: Race Conditions & State Async (并发条件竞争与状态机)
<!-- L1:START -->
1. 识别限额/幂等关键操作：支付、提现、领券、库存扣减、密码重置。
2. 构造并发时间窗请求包 (并发 Burst/Turbo)，探测竞争漏洞。
3. 验证幂等令牌机制是否存在先验校验后扣减的时序缺陷。
4. 收集双重入账、负数库存等状态异常差异化响应证据。
<!-- L1:END -->
<!-- L2:START -->
## 操作指南
- 采用多线程或 HTTP/2 单连接多路复用技术对齐请求时间戳。
- 观察并对比并发操作前后的账户余额/资源计数器。
- 确认锁机制（如分布式 Redis 锁、数据库行级锁）是否存在漏锁。

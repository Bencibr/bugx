# BugX L2 专项规则：内存泄露与资源管理规则（Resource & Memory Safety）

## 1. 核心检查模式
在挖掘与修复中，必须排查以下典型资源泄露缺陷：
1. **文件描述符未释放**：打开文件、网络 Socket、子进程管道后未在 `finally` 块或 `with` 上下文中保证关闭。
2. **数据库与连接池泄露**：获取连接或事物后未在异常路径执行 `rollback` / `release`，导致连接池耗尽死锁。
3. **全局生命周期引用滞留**：在全局缓存、长生命周期单例中累积对象引用，缺乏 LRU 或 TTL 淘汰机制。
4. **后台协程/线程孤儿**：启动的异步任务或轮询工作线程未监听生命周期取消信号，主程序退出时陷入僵尸状态。

## 2. 验证与断言方法
- 压力循环多次调用目标接口（如执行 1,000 次操作）；
- 结合 `gc.collect()` 比对对象增长数，以及检查当前进程打开的 FD 句柄数（如 `lsof -p <PID>`）；
- 若句柄数或内存单调线性增长，固化为 Memory Leak Finding。

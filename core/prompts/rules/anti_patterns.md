# BugX L2 专项规则：反模式与禁止行为清单（Anti-Patterns）

## 1. 证据造假与虚构行为（死刑红线）
1. **虚构 Finding**：严禁提交未实际复现、无确凿异常堆栈或无最小复现脚本的 Finding。
2. **模拟/伪造测试通过**：严禁在未真正执行测试进程的情况下声称“测试全部通过”。
3. **消除断言以掩盖失败**：严禁通过删除断言、注释被测代码或将断言改为无条件 True 来逃避测试失败。

## 2. 架构与边界侵入行为
1. **污染生产业务代码**：严禁将被测项目内部源码引入对 `.bugx/` 或 BugX 工具链的依赖。
2. **泄露测试数据与凭据**：测试产生的临时文件与 Mock 凭据必须局限在 `.bugx/` 或测试沙盒目录，严禁提交进 Git 版本库。
3. **篡改基线与历史账本**：严禁手动篡改 `coverage-evidence.json` 或 `bugx-life.json` 以虚报覆盖率。

## 3. 过程与执行反模式
1. **频繁全量测试**：严禁在单点修复时跑全量测试套件；必须改哪个模块只跑对应模块的定向测试。
2. **过度重构**：修复 Bug 时严禁大面积重构不相关模块；必须保持最小侵入性修复。
3. **静默吞异常**：严禁在修复时添加裸 `except: pass` 或忽略关键错误，必须保留原始错误语义或妥善处理。
